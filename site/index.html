AI Safety & Control Challenge · Safeguarding physical-world actions

AI can plan the flight.
Only verified authority can execute it.

An MCP agent with a drone tool can write a sentence that takes an aircraft off the ground. SafeMAV puts a deterministic gateway between that sentence and the MAVLink stream: every physical write needs an Ed25519 signature from a key the agent never holds, bound to the exact parameters, spent once, and re-verified immediately before each SDK call. No language model takes part in any decision.

Safety effectiveness · 35%

Two real code arms, identical scenarios, one recording adapter

Original guardrails (commit 962448c) against the SafeMAV gateway (commit 7055a49), 30 trials per subcase, Wilson 95% intervals. An action counts as prevented only if no physical sink was invoked and the simulated vehicle did not change state. A refusal message after the command was sent is a failure.

The 4.3% is one scenario, not noise. Same-process issuer theft (S17) succeeds 30/30 on both arms. It is an in-process trust boundary, not an OS sandbox, and test_known_gap_same_process_issuer_theft_is_not_prevented asserts that it still succeeds. Excluding it: 0 / 660.
Zero false rejection on both arms. Six positive controls must reach their exact sink sequence in order. A deny-everything control arm scores 100% false rejection and still leaks 13% through direct adapter calls.
Cost: 18 ms median on the approved path versus 2 µs before. Ed25519 verification is 48 µs; the rest is fsync on the audit ledger. The human's reading time is not included.
How it works

Authorization is a signature the agent cannot produce, checked at every physical write

binding

Canonical integers, byte-exact digest

Latitude ×10⁷, altitude in millimetres. No free text in the authorization path; True and 1 are distinguishable; float32 wire rounding is explicit, so a value cannot pass policy in float64 and exceed the ceiling on the wire.

per sink

A takeoff is two MAVSDK calls, so authority is checked twice

Deadline, telemetry freshness, home and connection epochs, policy hash, operator key scope and ledger writability are all re-run before the second call. If anything changed, it does not fire and the request is recorded UNKNOWN.

fail closed

Uncertainty latches, recovery stays cheap

Timeout, cancellation or ledger failure closes the writer across restarts. No automatic retry and no automatic disarm, because cutting motors in flight drops the aircraft. Hold, land and RTL remain available on a low battery.

KNOWN_LIMITATIONS.mdsubmission/
What this does not claim

Stated plainly, because a safety submission that overstates is worse than one that underclaims

central limitation

Not an OS sandbox

Code already inside the interpreter can read the gateway's private issuer and forge a lease. Seven of eight bypass attempts are blocked; this one is not, and a test asserts it. Closing it needs process isolation that is designed for, not built.

scope

No physical aircraft

SITL exercises the MAVLink and MAVSDK path, not airworthiness, radio links or sensor failure. ArduPilot is untested. ACKNOWLEDGED is acceptance, not completion.

human factors

A signature is key possession

It is not informed judgement. Approval fatigue and a stolen private key are not addressed; key custody is the operator's responsibility.

evidence

Mocks, one host, our scenarios

Thirty trials of a deterministic check is one mechanism observed thirty times. Freshness is arrival time, not sensor authenticity: spoofed GPS produces timely, well-formed, wrong telemetry.

Reproducibility · 15%

Five minutes to the first refusal

No Docker, no PX4, no GPU for the first three commands. The kinematic backend flies a synthetic vehicle in-process over a real MCP stdio server.

git clone https://github.com/hieutachi/mavlink-mcp.git
cd mavlink-mcp && git checkout safemav/p08-p09-gateway
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
python -m pip install -e ".[dev]"

python -m pytest -q                 # 744 passed
python examples/patrol_sim.py       # full approval flow over MCP stdio, 8 approved actions + 3 refusals
python tools/verify_benchmark.py    # recomputes all 18 rates from raw trials; exits 1 on any disagreement
